Vulkan renderer · Minecraft 1.12.2 · CleanroomMC

CELTIUM

A native Vulkan renderer for Minecraft 1.12.2.
Celtium creates the game window without an OpenGL context and draws terrain, entities, items, particles, sky, clouds and the GUI into Vulkan images — a renderer replacement, not a GL translator.

Built from Celeritas. Celtium was a historical proposed name for element 72, hafnium.

01 — Features

A renderer, rebuilt on Vulkan

Shader packs, real shadows

Iris-style shader packs run through the pack route with working shadow maps. Cast shadows are verified, not assumed: on the shipped v0.3.0 jar, a pinned-time proof scene shows Complementary's pillar shadows appear, stretch and move with world time.

Native Demonica support

Demonica is supported natively in-core — its bundled GLSM layer talks to Celtium's compatibility surface directly. Menus, textured GUI draws and in-world programs are maintained against real packs, not emulated and not refused.

No OpenGL context

The window, swapchain, textures and framebuffers are Vulkan objects from the first frame. Terrain, entities, items, particles, sky, clouds and the GUI are drawn by native Vulkan passes that follow Minecraft's own semantics.

A GL-less layer for mods

Mods that call OpenGL directly are served by a compatibility layer covering display lists, immediate mode, VBOs, FBOs and legacy state — applied only to mods, only where they call GL. The 1.12.2 ecosystem keeps working.

Modpacks, verified

SkyFactory 4, All the Mods 3, RLCraft, SevTech: Ages, Project Ozone 3 and Nomifactory CEu are verified end-to-end: zero Vulkan validation errors, full log review, same-pose picture comparison on AMD and Intel. Supersymmetry (188 mods) and Enigmatica 2: Expert – Extended (≈430 mods) reach the world with zero validation errors.

An overhaul in progress

The renderer is being rebuilt underneath: a global vertex arena, region offsets via SSBO, explicit allocation on the hot path, pipeline-state caching. Every landing passes a 1,200+ test gate on real hardware before it reaches main.

02 — Performance

Measured, not claimed

Celtium is benchmarked against Celeritas — the renderer it succeeds — in paired runs on the same machine: same scene, alternating arms, warm-window medians. The figure below is frame time at warm P50 (the median frame once the world has settled; lower is better). Results are scene-dependent, and this page says which is which.

04 — Install

Up and running

  1. Prepare a Cleanroom instance

    Use a Cleanroom Relauncher instance: CleanroomMC 0.7.12-alpha or later (0.7 line), LWJGL 3.4.3, and a Java 25+ game JVM.

  2. Drop the jar in mods/

    Download celtium-forge-mc1.12.2-0.3.0.jar from the v0.3.0 release and put it in mods/. Use the plain jar — not -dev or -reobf.

  3. Remove Celeritas

    Install one renderer, not both. Celtium keeps the celeritas mod ID and resource namespace, so the two cannot coexist.

  4. Launch and enter a world

    For dynamic lights, use Pulsar Lighting Engine; Alfheim is unsupported. Then check the GUI, menus, creative tabs and tooltips like any first run.

05 — Roadmap

What is next

v0.3.1 · Bugfix release · In preparation

Fixes already landed on main

  • Enchanting-table crash. Placing an enchanting table (or another tile-entity special renderer) crashed the shipped jar with MemoryStack exhaustion in the immediate-mode flush. Fixed.
  • 0×0 surface crash. When the window surface reported 0×0 — minimise, alt-tab, mid-resize — the swapchain escalated to a crash. It now waits for a real size. Fixed.
  • Demonica menu corruption. Text as white blocks, black background, missing textures: three stacked causes in the GLSM compatibility path. Fixed, and verified with proof runs.
  • Performance work. The graphics-pipeline re-creation fix, the global vertex arena and the region-offset SSBO, landed since 0.3.0.

v0.3.1 ships when the known-defect list is empty — not on a calendar date.

v0.4.0 · Next major* · Target: late December 2026

The release criteria

  • No bugs in large modpacks — the verified-pack standard, held at pack scale.
  • Always significantly outperform Celeritas — at least 1.25× at warm P50 in every scene of a fixed scene set, no exceptions.
  • Rendering optimisation almost fully overhauled — the rebuild programme, finished.
  • Mesh shaders on supported GPUs.

These are the goals the work is measured against, not promises. *Celtium follows zerover: while on 0.x, the middle number is effectively the major version.
